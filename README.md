# magento-doc-generator

Turns a Magento 2 codebase into browsable documentation: it reads every module's PHP and
XML, extracts the **wiring** a developer actually needs (plugins, observers, preferences,
cron, web API, GraphQL, queues, DB schema, DI graph, admin config fields), and publishes a
page per module to [DocuHub](https://github.com/nicolasperic/docuhub).

The admin **config fields** (`etc/adminhtml/system.xml`) are extracted into `doc.config[]` —
each field's path, admin element id, label, type, source/backend model, scope, dependencies
and whether it already has `<comment>` help. This is the ground truth behind three
consumers: the `MageOS_InlineDocs` popovers (matched by element id), the longer modal
content, and the Config section of a module's AGENTS.md. Across Mage-OS core it finds 1,120
fields, only 356 (≈32%) with any help text.

Two repos, one job each: **DocuHub** is the wiki that stores and serves the docs;
**this** is the pipeline that keeps them true to the code.

## Why not just ask an LLM to read the module?

Because it will confidently invent a plugin that doesn't exist. The extraction step here is
**deterministic** — a `nikic/php-parser` AST walk plus real XML parsing — and it emits a
`module.doc.json` that is ground truth. The narrative layer writes prose *from that JSON*,
so the class names, event names and plugin targets in the finished page are the ones in the
code. Prose is generated; wiring is extracted.

## Install

```bash
git clone https://github.com/nicolasperic/magento-doc-generator.git
cd magento-doc-generator
composer install

cp .env.example .env         # point MDG_MODULES_DIR at your modules
cp taxonomy.example.php taxonomy.php
```

`extract.php` needs `nikic/php-parser`. `composer install` provides it, but if you'd rather
run against the host project's autoloader, pass `--vendor-autoload=/path/to/vendor/autoload.php`
(it also walks up looking for one).

## The pipeline

```
 extract.php      code ──AST/XML──▶ module.doc.json         deterministic, no LLM
 (narrate)        module.doc.json ──▶ README.generated.md   prose, from the JSON only
 apply-readme.php README.generated.md ──▶ module/README.md  marker splice, edit-guarded
 derive_labels.php  all module.doc.json ──▶ labels.tsv      Domain/Integration/Status
 ingest.php       bundle ──HTTP──▶ DocuHub                  timestamp-guarded upsert
 track.php        progress across the whole run             pending/done/failed/skip
```

### 1. Extract

```bash
php extract.php /path/to/modules/module-checkout-express > output/module-checkout-express/module.doc.json
```

Emits classes (with constructor deps, interfaces, API annotations), the wiring lifted from
`di.xml` / `events.xml` / `crontab.xml` / `webapi.xml` / `db_schema.xml` / `queue_*.xml`,
a flat `components` list (the *verbs* of the module), `edges` for the graph view, and `stats`.

### 2. Narrate

The narrative layer reads `module.doc.json` and writes `README.generated.md` in the shape
described in [`docs/DOC_TEMPLATE.md`](docs/DOC_TEMPLATE.md) — a one-paragraph summary, a flow
sketch, a key-components table, the gotchas, and an auto-extracted wiring block. Everything
it asserts must be traceable to the JSON.

### 3. Apply

```bash
php apply-readme.php /path/to/modules/module-checkout-express output/module-checkout-express/README.generated.md
```

Writes the module's `README.md` **without ever clobbering hand-written content**:

| Situation | What happens |
|---|---|
| No README, or a trivial one | writes the generated file |
| README has our `<!-- doc:generated -->` markers | replaces **only** that block, keeps Team Notes |
| Someone hand-edited *inside* the generated block | refuses (hash + mtime mismatch) unless `--force` |
| Real hand-written README, no markers | refuses; `--merge` prepends the generated block instead |

### 4. Label

```bash
php derive_labels.php      # writes labels.tsv + prints a coverage summary
```

Three families — **Domain** (what it's about), **Integration** (what it's coupled to),
**Status** (Legacy / Stub). Integration and Status are derived automatically; Domain is a
curated map in `taxonomy.php`. Modules with no domain are reported as `UNCOVERED`.
See [`docs/TAXONOMY.md`](docs/TAXONOMY.md).

### 5. Ingest

```bash
php ingest.php module-checkout-express --dry-run     # inspect the payload
php ingest.php module-checkout-express               # POST to DocuHub
php backfill_labels.php                              # re-send every module (--force)
```

Generated content and human content live in different fields on the DocuHub page and are
guarded differently — generated by **timestamp** (newer wins), human by **optimistic
version** (stale save = clean 409, not a silent overwrite). So a nightly re-scan can refresh
every module's reference without ever touching someone's runbook.
Full contract: [`docs/API_CONTRACT.md`](docs/API_CONTRACT.md).

### Tracking a full run

```bash
php track.php init            # register every module-* dir as pending
php track.php status          # progress bar + counts
php track.php next 10         # next 10 pending dirs
php track.php set module-x done "import created (HTTP 201)"
```

State is a greppable TSV, so a long run survives interruptions and you can see exactly
where it stopped.

## Configuration

Everything resolves from the environment (or a `.env` next to `config.php`); real env vars win.

| Variable | Default | Purpose |
|---|---|---|
| `MDG_MODULES_DIR` | — | directory holding the `module-*` dirs (or `--modules-dir=PATH`) |
| `MDG_OUTPUT_DIR` | `./output` | where bundles are written |
| `MDG_TAXONOMY` | `./taxonomy.php` | label taxonomy (falls back to the shipped example) |
| `MDG_LABELS_FILE` | `./labels.tsv` | derived labels |
| `MDG_STATUS_FILE` | `./modules.status.tsv` | run tracker state |
| `DOCS_INGEST_URL` | `http://localhost:3001/api/docs/ingest` | DocuHub endpoint |
| `DOCS_INGEST_TOKEN` | — | bearer token for ingest |

Generated output and derived state are gitignored: this repo holds the tool, your docs live
in your codebase and in DocuHub.

## Requirements

PHP 8.1+ with `json`, `curl` and `simplexml`, plus `nikic/php-parser`.
